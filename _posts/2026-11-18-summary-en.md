### [OpenAI launches GPT-6.2 Astra and Sol](https://openai.com/index/introducing-gpt-6-2-astra-sol/) ⭐️ 9.0/10

OpenAI launched GPT-6.2 Astra for difficult professional tasks and GPT-6.2 Sol for everyday multimodal and tool-using work, making both immediately available to ChatGPT Plus, Pro, Enterprise, and Edu users as well as through Codex and the API. OpenAI says Astra gained 5.2 points over GPT-6 Astra on Agents’ Last Exam while costing less than one-third as much per task, and it priced Astra’s API at $8 per million input tokens and $40 per million output tokens—20% below GPT-6 Astra. The company’s safety card says both models reach its Preparedness Framework cybersecurity “Critical” threshold, while Astra’s self-improvement capability reaches “High,” prompting tighter restrictions on high-risk cyber assistance.

hackernews · OpenAI News · Nov 17, 17:46 · [Discussion](https://news.ycombinator.com/item?id=50535230)

**「Background」** OpenAI introduced GPT-6 Astra in September 2026 as an alignment-focused step over GPT-5.6 Sol; GPT-6.2 follows the canceled, safety-delayed GPT-6.1 Astra and divides the updated line into Astra for difficult professional work and Sol for routine multimodal and tool use. OpenAI says GPT-6.2 Astra is its first externally deployed model rated High for AI self-improvement, while both new models reach Critical for cybersecurity and High for biological and chemical capabilities under its Preparedness Framework.

**「Lower agent costs, with evaluation caveats」** Teams running tool-heavy API agents should re-cost their existing workflows: OpenAI says GPT-6.2 Astra scored 5.2 points above GPT-6 Astra on Agents’ Last Exam at less than one-third of the cost, while its API price is $8 per million input tokens and $40 per million output tokens, 20% below GPT-6 Astra. In one early data-analytics test, Astra and Sol task costs fell from roughly $20 to $4 and $2.6 to $1.2, respectively, with similar accuracy and fewer tool calls; however, some runs stopped before finding the answer and reviewers criticized office-document quality, so teams should benchmark completion and output quality before switching.

**「Early tester reports」** One analytics-exam tester reported that Astra’s cost fell from roughly $20 to $4 and Sol’s from $2.60 to $1.20 at similar accuracy, attributing the savings to 20% fewer tokens and fewer tool calls; the tester also observed some early stops that missed the requested answer. Another commenter judged the slide, workbook, and memo examples weaker than older-model outputs, while a separate PacBench run scored Astra 92 in 6.6 minutes for $2.04 and Sol 87 in 6.3 minutes for $0.49; these are individual results rather than independent consensus.

The reported RMB 11.16 average cost per simulated task compares directly with the predecessor’s RMB 26.58, while independent model listings confirm the 1M-token context and November 16, 2026 release date; however, the detailed cost figure is company-reported through the source account.

The article presents Tencent’s Hy4 Flash as a lower-cost, faster model for routine agent workloads, reporting 224B total parameters, about 12B active parameters, multimodal support, a 1M-token context window, and a KV cache sized at roughly 1/24 of Hy3 and 1/6 of Hy4. It lists official goals of more than 150 tokens per second and approximately one-twentieth of Hy4’s per-task cost, alongside prices of RMB 0.5 per million input tokens, RMB 2 per million output tokens, and RMB 0.02 for cached input, but these vendor claims and pricing details are not independently verified in the cited tests. In four limited hands-on cases, Hy4 Flash completed a complex office task in 1 minute 14 seconds versus DeepSeek-V4.1-Flash’s 4 minutes 8 seconds, but was slower on an image test and missed a misdrawn bar chart; it also fixed four inventory-system defects in 2 minutes 5 seconds versus Hy4’s 3 minutes 49 seconds, while producing a faster 21-page paper-to-PPT draft with layout and formatting defects. The article therefore positions Hy4 Flash for first drafts and routine coding work, while recommending stronger models, additional tests, and human review for long-running engineering, high-risk decisions, and polished presentations; its limited and unpublished test protocol leaves the official performance targets unconfirmed.

rss · 人人都是产品经理 · Nov 18, 02:38

**「Background」** The relevant baseline for evaluating an agent model is the cost of a multi-step workflow rather than a single prompt: the article cites a study of 500 real coding problems across eight models in which one agent attempt averaged about 4.17 million tokens and $1.86, with latency and tool usage accumulating across repeated model calls. Hy4 Flash targets these high-frequency workloads with a 224B-total, approximately 12B-activated architecture that includes Engram parameters and supports a 1M-token context window, leaving longer or higher-risk engineering and decision tasks to stronger models and additional validation.

**「Deployment impact」** For teams running many agent calls, the trial supports routing high-frequency, regression-testable work—such as routine code fixes, document processing, and first-draft slide decks—to Hy4 Flash, while enforcing budget caps, caching, automated number-and-chart checks, and human review for final outputs. Hy4 Flash completed the inventory fix in 2 minutes 5 seconds versus Hy4’s 3 minutes 49 seconds, but it missed a chart-scale error and produced a less polished slide deck, so long-running engineering, high-risk decisions, and customer-facing materials should remain with a stronger model or reviewer. Because this was a small test drawn from a secondary article rather than an independent benchmark, teams should measure cost, latency, and failure rates on their own workloads before shifting production traffic.

**「Background」** Datasette Lite is Simon Willison’s attempt to run the full server-side Datasette application in a browser, initially as a joke but later as a practical way to share demos and reproduce bugs without deploying a server. The first implementation used a Pyodide web worker and injected HTML into the page, but that broke JavaScript because scripts inserted with innerHTML do not execute and additional assets could not be loaded reliably.

**「Solution」** The rewrite uses a Service Worker to intercept requests, while each tab’s parent page embeds an iframe and prefixes requests with a random /app/&lt;session&gt;/ identifier so one tab’s Datasette instance, plugins, and settings cannot leak into another. Query parameters make the browser environment reproducible: install can add PyPI or wheel-hosted plugins, including JavaScript tools; url can load SQLite databases, JSON, CSV, or SQL scripts; metadata supplies configuration; ref selects a Datasette release or Git reference; and sqlite selects a specific WebAssembly SQLite build. In practice, the author used links against Datasette 1.0a42 and 1.0a43 to reproduce and then demonstrate a pagination fix, built wheels for 163 SQLite versions plus a side-by-side SQL comparison tool, and required remote database URLs to provide open CORS headers. Willison argues that the pattern could support lightweight preview environments for many Python applications because native extensions can be compiled for Pyodide, while acknowledging that PostgreSQL and MySQL in WebAssembly remain less-trodden than SQLite.

**「Takeaway」** Service-worker routing and URL-addressable configuration can turn server-oriented Python applications into shareable, disposable browser environments for demos, testing, and bug reproduction, with SQLite-backed workflows offering the clearest path today.
